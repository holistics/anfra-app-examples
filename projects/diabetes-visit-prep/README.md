# Diabetes Visit Prep

Prepares a diabetes clinic visit: the patient's body colored organ by organ by clinical status, two years of it as a time-lapse, and a drill into the cause.

- Demo: https://diabetes-visit-prep.pages.holistics.dev/apps/diabetes-visit-prep
- Video: https://media.holistics.io/anfra/competition-2026/diabetes-visit-prep-demo.mp4
- Author: Quan Nguyen

## Data

Five synthetic patients over two years (CGM readings, labs, blood pressure, insulin doses, treatment events, complication screenings), generated into DuckDB by the seeded script `scripts/generate.mjs`. No real patient data is in this folder. The 3D body uses BodyParts3D (© The Database Center for Life Science, CC BY 4.0) and Anny by NAVER LABS (MakeHuman assets, CC0); `apps/_lib/body-model.js` carries the credits.

## About

A diabetes clinic app built on [anfra](https://anfra.ai) for the 2026 anfra App Competition. It shows a patient's body, organ by organ, colored by a governed clinical status, plays two years of it as a time-lapse, and drills into the cause. Every threshold and formula lives in the AML under `models/` and `datasets/`; the app pages in `apps/` hold no clinical constants.

All patient data is synthetic, generated by a seeded script.

## Run it

Needs Node 20+ and the anfra CLI (`curl -fsSL https://anfra.ai/install.sh | bash`).

```sh
npm install
npm run setup      # writes .anfra/data_sources.yml for this clone, then generates data/health.duckdb
anfra validate
anfra serve        # http://127.0.0.1:7878/apps/diabetes-visit-prep
```

After regenerating the data (`npm run generate`), restart `anfra serve`: it keeps the old DuckDB file open.

`anfra serve` reloads an open page when the page or the AML changes, but not when a shared file in `apps/_lib/` does. While editing those, also run `npm run watch-lib`, which touches the pages so they reload.

## Deploy

The app is public at https://diabetes-visit-prep.pages.holistics.dev/apps/diabetes-visit-prep, deployed with `proto` (Holistics' prototype deploy CLI). It's served the way demo.anfra.ai serves its apps: [anfra-host-example](https://github.com/holistics/anfra-host-example) on port 5173, which passes on only the operations a Data App needs (rate-limited per visitor) to `anfra serve --no-apps` on loopback. The Dockerfile patches the pinned host to also pass on `core.lineage`, which the metric tooltips read their text from; later host versions allow it themselves. `anfra serve` has no login, so it's never exposed directly. The image generates the data at build time and opens it read-only, without file access: `/api/core.query` runs any SQL a visitor sends.

One-time setup:

```sh
curl -fsSL https://docs.pages.holistics.dev/install.sh | sh
proto login
gh auth refresh -h github.com -s write:packages
gh auth token | docker login ghcr.io -u "$(gh api user --jq .login)" --password-stdin
```

Then, after committing:

```sh
docker/deploy.sh    # builds for linux/amd64, pushes to ghcr.io/<you>/diabetes-visit-prep, runs proto deploy
```

`proto deploy` opens a PR on `holistics/prototypes-deploy`. That PR is the site, so keep it open: closing it takes the site down. `proto status diabetes-visit-prep` and `proto logs diabetes-visit-prep` show how it's doing.

proto gives an image app a 1 GiB memory limit, and the app peaks just over that with two visitors clicking at once. So the PR's `apps/diabetes-visit-prep/values.yaml` sets `resources.requests.memory: 1Gi` and `resources.limits.memory: 2Gi`, as demo.anfra.ai's does. Redeploys keep that edit.

To try the image locally first:

```sh
docker buildx build --platform linux/amd64 --load -t diabetes-visit-prep:local .
docker run --rm -p 127.0.0.1:5199:5173 -e ANFRA_SITE_URL=http://127.0.0.1:5199 diabetes-visit-prep:local
```

## Layout

| Path | What |
|---|---|
| `scripts/generate.mjs` | Seeded synthetic data generator → `data/health.duckdb` |
| `scripts/check-story.mjs` | `npm run check`: confirms the generated data still tells the demo story |
| `test/integration/` | `npm run test:integration`: runs the AML through `anfra query` and checks that the time-lapse ends on today's governed status for every patient, that each report window gives the same numbers as a `where()` and as a date filter on its bounds, and that the glucose timeline's shares from day counts match the report metrics (needs `anfra ingest` first) |
| `scripts/reload-pages-on-lib-change.mjs` | `npm run watch-lib`: reloads open pages when `apps/_lib/` changes |
| `models/`, `datasets/` | AML: the governed models, metrics and statuses |
| `apps/` | Data App pages, one HTML file each |
| `Dockerfile`, `docker/` | The deploy image: the host, anfra, and the data generated at build time; `docker/deploy.sh` ships it |
