# anfra interaction patterns

A gallery of 54 analytical interaction patterns for anfra Data Apps: filters, selections, dates and time, drilling, tables and calculations, scenarios and saved state. Each card has a trailer, a live mini Data App on the ecommerce sample, its AQL and SDK code, hand-written SQL for comparison, and a prompt to copy.

- Demo: https://anfra.ai/interaction-patterns/
- Video: https://media.holistics.io/66b3bb6d-interaction-gallery.mp4
- Author: Chinh (lelouvincx)

This is a source snapshot of [holistics/anfra-interaction-patterns](https://github.com/holistics/anfra-interaction-patterns) at commit `c0a1c3de41b1ee255beb5ec10e7fad0c4155739b`. The original repository and live deployment stay there; its GitHub deployment workflow is not copied here. Run the commands below from `projects/interaction-patterns/`.

It is one HTML page served by a small Node server. The server also passes the page's queries to an anfra server, which serves the `ecommerce` Dataset in `anfra/`. The repo has everything it needs: it does not depend on anfra-demo-data.

## Layout

- `gallery/`: the page source. `build.mjs` puts it together into `site/interaction-gallery.html`.
  - `agents.mjs`: writes `skill/` from the same cards.
  - `gallery.src.html`, `design.css`, `engine.js`, `iso.js`, `live.js`: the page, its styles and its code.
  - `demos.js`: the cards. `steps/`, `prompts/` and `sql/` hold each card's steps, prompts and hand-written SQL, keyed by card id. `holistics.json` holds the Holistics comparison.
  - `live-apps/<card id>.js`: the live mini Data App for each card. `LIVE-APPS.md` describes how to write one.
  - `aql/` and `aql-results.json`: the AQL the trailers use, and its saved results. `collect.sh` runs `aql/` again.
- `assets/`: trailer data, the Inter and Geist Mono fonts (embedded in the page) and the two recorded trailers in `media/`.
- `sdk/anfra-host.iife.js`: `@holistics/anfra-sdk` 0.8.0's host and API modules bundled from `sdk/entry.js`, embedded in the page.
- `timeline/`: `make.py` draws `timeline.svg`, the Dates & time diagram.
- `deploy/`: the server (`server.mjs`), the container start script and the `Dockerfile`.
- `anfra/`: the anfra folder the server serves, with only the `ecommerce` Dataset.
  - `datasets/ecommerce.dataset.aml` and `models/ecommerce/`: the Dataset and its six models (customers, orders, order items, products, markets, sessions).
  - `db/duckdb/ecommerce.duckdb`: the data, read-only. `db/build_ecommerce_duckdb.py` builds it from `db/seed.dump.sql`, and `db/duckdb_stamps.sh` checks it still matches its seed.
  - `.anfra/`: the data source (`ecommerce_duckdb`) and the AML source.
- `skill/`: the gallery for coding agents, laid out as a skill and generated by `build.mjs` (don't edit it by hand; commit it after a build, and CI fails when it is stale). `SKILL.md` is the entry with relative links, `AGENTS.md` the same guide with absolute links, `llms.txt` and `llms-full.txt` the index and every page in one file, and `references/<card id>.md` one page per card with its AQL, SDK wiring and live-app source. `build.mjs` copies it into `site/`, so anfra.ai serves `llms.txt`, `AGENTS.md` (and `agents.md`) and `references/<card id>.md` at the root.
- `tools/sqlcheck.py`: runs each card's hand-written SQL on the ecommerce DuckDB file.

The ecommerce Dataset was copied from [anfra-demo-data](https://github.com/holistics/anfra-demo-data) at `831f1d4`, and has its own copy here so the gallery doesn't change when demo.anfra.ai does. To take a later change, copy the files again and run the gallery's queries (`sh gallery/collect.sh`) to see what moved.

## Data

All bundled data is synthetic ecommerce sample data, not real customer or internal data. `anfra/db/seed.sql` generates fictional customers (`Customer 1`, `customer1@example.com`, and so on), products, orders and sessions. `seed.dump.sql` freezes that sample, and the bundled DuckDB file is checked against the seed by `duckdb_stamps.sh`. The data source uses only that local read-only file; no database credentials are needed.

`site/` is generated and not committed.

## Build the page

```sh
node gallery/build.mjs          # writes site/ (Node 20 or later, no dependencies)
python3 timeline/make.py        # only after changing the timeline
```

## Run it locally

```sh
(cd anfra && anfra serve --no-apps --addr 127.0.0.1:7878) &
PORT=8080 ANFRA_URL=http://127.0.0.1:7878 node deploy/server.mjs site
```

Open http://127.0.0.1:8080/interaction-gallery.html.

Agents read http://127.0.0.1:8080/llms.txt and http://127.0.0.1:8080/references/date-filter.md.

## Change the data

Edit `anfra/db/seed.dump.sql`, then rebuild the DuckDB file with the DuckDB version anfra bundles, and commit both with the new stamp:

```sh
cd anfra && uv run --no-project --with duckdb==1.4.2 python db/build_ecommerce_duckdb.py
```

## Build and run the image

The image is the official anfra image with Node added, `anfra/` as `/repo`, the page and the server. The Dockerfile builds the page itself. `start.sh` runs `anfra serve` on `/repo` at 127.0.0.1:7878 and the gallery server on port 8080.

```sh
docker build -f deploy/Dockerfile -t anfra-interaction-patterns .
docker run --rm -p 8080:8080 -e BASE_PATH=/interaction-patterns anfra-interaction-patterns
```

Open http://127.0.0.1:8080/interaction-patterns/. The files must be readable by the container's `anfra` user: with a umask of 077, run `chmod -R go+rX .` first, or `db/duckdb_stamps.sh` fails the build.

## Server settings

`deploy/server.mjs` reads these environment variables:

| Variable | Default | What it does |
|---|---|---|
| `BASE_PATH` | (none) | Serves everything under this prefix, such as `/interaction-patterns` on anfra.ai. The bare prefix redirects to it with a trailing slash, and paths outside it return 404. The page finds `api/` and `media/` relative to itself, so it needs no change. |
| `QUERY_RATE_LIMIT` | 600 | `core.query` and `/api/run` requests a minute per visitor, as on demo.anfra.ai. Over it, the server returns 429. |
| `EXPORT_RATE_LIMIT` | 10 | `core.query.export` requests a minute per visitor. |
| `CLIENT_IP_HEADER` | (none) | The header that names the visitor, such as `cf-connecting-ip` behind Cloudflare. |
| `TRUST_PROXY` | (off) | With `1` and no `CLIENT_IP_HEADER`, the visitor is the last address in `X-Forwarded-For`, the one the proxy in front appended. Otherwise it is the socket's address. |

`core.show` has no limit. Limits are counted per container, in one-minute windows.

## Original repository deployment

In the original repository, `.github/workflows/build.yml` builds the image for linux/amd64 on every pull request and push to `main`, and pushes `ghcr.io/holistics/anfra-interaction-patterns:<commit>` from `main`. It needs no secrets beyond the workflow's own token. This examples copy does not run that workflow or deploy the site.

From `main`, it then writes the new tag into `k8s/versions.yml` on the `release` branch. ArgoCD's `anfra-interaction-patterns` Application (in holistics/deploy) reads that file and deploys the image to anfra.ai/interaction-patterns. To roll back, set an older tag there.
